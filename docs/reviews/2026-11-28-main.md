## Summary
This change implements custom review rules, per repository overrides, curated example pull requests, dual channel feedback learning, bounded Tier 1 prompt injection, and the analytics and reviews console pages for Spec 0009. Overall the schema design, credential redaction, XML escaping, webhook actor association checks, and 25 rule / 5 example cap enforcement are well structured and pass typecheck and lint checks across both workspaces. However, there are four major issues you should resolve before merge: a concurrent feedback race condition and duplicate feedback event logging, a React effect dependency bug in `ReviewsView` that flashes and refetches on every selection, path scoped rule dropping and missing integration tests in `RunAutonomousLoopUseCase`, and direct infrastructure imports inside the application layer `AnalyticsService`.

## Major
### 🟠 Concurrent feedback race condition and duplicate feedback rows, `apps/agent/app/application/use_cases/review_feedback.py:60`
**Problem**: `ReviewFeedbackUseCase.submit_feedback` fetches the finding via `get_finding_with_review` (`apps/agent/app/infrastructure/db/repositories/review_feedback_repository.py:77`) without a row lock, and calls `record_feedback_event` at line 67 before checking `finding.feedback_state == feedback_type` at line 103. In addition, `get_preference_with_feedback(..., for_update=True)` at line 96 locks nothing when no `review_learned_preferences` row exists yet for `(repo_id, pattern_key)`.
**Why it matters**: Submitting identical console feedback twice writes a duplicate row to `review_finding_feedback` even though counters stay unchanged. Worse, two concurrent feedback requests for the same finding (or the first feedback on a new pattern key) can both read stale `feedback_state`, double increment `dismiss_count` and `consecutive_dismissals` in violation of `AC-4`, or collide on `uq_review_learned_prefs_repo_pattern` with an unhandled `IntegrityError` (HTTP 500).
**Suggested fix**: Lock the `PRReviewFindingModel` row with `with_for_update()` before reading `feedback_state`, skip inserting console feedback events when `finding.feedback_state == feedback_type` (after claiming `github_event_id` when present), and handle first time preference creation atomically with PostgreSQL `INSERT ... ON CONFLICT DO UPDATE` or by locking the parent repository row in `upsert_preference`.

### 🟠 `ReviewsView` refetches list and flashes skeleton on selection, `apps/web/src/app/(console)/reviews/reviews-view.tsx:160`
**Problem**: `selectedReviewId` is included in the dependency array of the `loadReviews` `useEffect` at line 160, and initial load also calls `setSelectedReviewId` at line 135.
**Why it matters**: Every time you click a different pull request review in the list (line 352), the effect runs again, sets `isLoadingList(true)`, replaces the entire two column layout with the loading skeleton at line 303, refetches `/api/v1/reviews`, and unmounts the detail panel. Initial page load also triggers a redundant list fetch.
**Suggested fix**: Remove `selectedReviewId` from the `loadReviews` `useEffect` dependency array and use a functional state update (`setSelectedReviewId((prev) => ...)`) inside `loadReviews` when auto selecting or clearing the active review.

### 🟠 Autonomous loop drops path scoped rules when `target_file` is omitted, `apps/agent/app/application/use_cases/run_autonomous_loop.py:835`
**Problem**: `RunAutonomousLoopUseCase._run_cycles` filters `merged_rules` against `target_paths = [options["target_file"]] if isinstance(options.get("target_file"), str) else []` before Forge runs, even though `task_context["target_file"]` defaults to `"src/solution.py"` at line 905 and background worker tasks do not pass `options["target_file"]`. Furthermore, `review_feedback_repo` and `review_examples_repo` loading at lines 855 and 877 are nested inside `if self._review_rules_repo is not None:`, and no test executes `RunAutonomousLoopUseCase` with custom rules.
**Why it matters**: When `target_paths` is empty, `ReviewContextService.rule_matches_files` tests rules only against `"README.md"`, dropping every path scoped rule (such as `src/**/*.py`) during real autonomous tasks even when Forge modifies matching files. Also, preferences and examples are skipped if `review_rules_repo` is omitted, and this branching logic is completely uncovered by tests.
**Suggested fix**: Move `review_feedback_repo` and `review_examples_repo` checks outside the `review_rules_repo` guard, pass merged active rules or match against actual modified paths parsed from `state["forge_diff"]` inside `task_graph.py` `reviewer_node` (falling back to `target_file` when the diff is empty), and add an integration test covering `RunAutonomousLoopUseCase._run_cycles`.

### 🟠 `AnalyticsService` violates Clean Architecture layer boundaries, `apps/agent/app/application/services/analytics_service.py:9`
**Problem**: `AnalyticsService` lives in `app/application/services/` while directly importing `sqlalchemy`, `AsyncSession`, `redis.asyncio`, and seven `app.infrastructure.db.models.*` ORM classes. Similarly, `list_organization_reviews` in `apps/agent/app/api/v1/endpoints/reviews.py:265` queries SQLAlchemy ORM models directly inside the FastAPI endpoint instead of calling `PRReviewRepository`.
**Why it matters**: Root `AGENTS.md` requires strict Clean Architecture separation where outer infrastructure and presentation layers depend on inner application ports via dependency inversion, never the reverse. Every other service in `app/application/services/` avoids direct SQLAlchemy and ORM imports.
**Suggested fix**: Define an `AnalyticsRepository` port in `app/application/ports/` and move the SQLAlchemy and Redis implementation into `app/infrastructure/db/repositories/`, and move the organization review list query into `PRReviewRepository`.

## Minor
### 🟡 `ContextBudgetAllocator` corrupts indices when pruning non contiguous lists, `apps/agent/app/application/services/context_budget_allocator.py:212`
**Problem**: When `custom_text` exceeds `CUSTOM_CONTEXT_MAX_TOKENS` (6,000 tokens), lines 215 to 233 pop one index from `kept_*_idxs` and pass `[entries[i] for i in kept_*_idxs]` back into `_pack_lines_within_budget`, which returns `0..k-1` indices relative to the sliced list instead of the original `matched_rules` / `pref_entries` / `example_entries` indices.
**Why it matters**: If an earlier oversized entry was skipped during initial packing (creating a gap in `kept_rule_idxs`, such as `[0, 2, 3]`), reindexing maps `kept_rule_idxs` back to the wrong `matched_rules` items and records incorrect `included_rule_ids` at line 247.
**Suggested fix**: Reassemble the XML wrapper directly from the remaining `kept_*_idxs` without reenumerating a sliced list, or track `(original_index, entry)` tuples inside `_pack_lines_within_budget`.

### 🟡 Missing `severity_override` UI control in `RepoRulesAndOverridesTab`, `apps/web/src/components/repositories/repo-review-tabs.tsx:288`
**Problem**: For inherited organization rules (`rule.scope === "org"`), `RepoRulesAndOverridesTab` renders enable/disable and reset buttons and passes `rule.override_severity` through unchanged, without providing any control to set or change `severity_override`.
**Why it matters**: `AC-1` and `AC-7` support per repository overrides for both `is_enabled` and `severity_override` on inherited organization rules in the `Rules & Overrides` tab, so admins currently cannot override rule severity from the web console.
**Suggested fix**: Add a severity override `Select` control next to the toggle button on organization rules when `isAdmin` is true.

### 🟡 Unvalidated `path_globs` bracket ranges can raise `re.error`, `apps/agent/app/application/services/review_context_service.py:78`
**Problem**: `_compile_globstar` translates `[...]` segments directly into regex character classes without catching `re.error`, and `ReviewRuleCreateRequest` / `ReviewRuleUpdateRequest` in `apps/agent/app/application/schemas/review_rules.py:26` only check that glob strings are non empty.
**Why it matters**: Saving a rule with a malformed bracket range such as `[z-a]` or `[]` succeeds at write time and later raises an unhandled `re.error` (HTTP 500) during PR review rule matching.
**Suggested fix**: Validate glob compilation in the request schema or `ReviewRulesUseCase` so invalid globs return HTTP 422, and fall back to escaping brackets in `_compile_globstar` if compilation fails.

### 🟡 `build_diff_summary_and_files` can slightly exceed `max_tokens`, `apps/agent/app/application/services/review_context_service.py:250`
**Problem**: `used_tokens` accumulates per file block token counts without counting the `"\n\n"` join separators added at line 285, and the character fallback slice `redacted[:approx_chars]` at line 289 is not verified against `count_tokens`.
**Why it matters**: When several small files pack right up to `1,500` tokens, separator tokens can push `cached_token_count` slightly past the `1,500` token cap specified in `AC-2`.
**Suggested fix**: Account for separator tokens in `used_tokens` and trim the fallback slice until `count_tokens(summary) <= max_tokens`.
